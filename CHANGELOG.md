# Changelog

All notable user-facing changes to LyraForge are documented in this file.

## [Unreleased] — 0.1.0-alpha

### Fixed
- **Windows default UAC Administrator launch & silent background subprocesses**: embedded Windows UAC `uac_admin=True` in `LyraForge.exe` (`packaging/lyraforge.spec`) plus source-mode auto-elevation via `pythonw.exe` / `ShellExecuteW("runas")` (`lyraforge.elevation`, with `--no-elevate` / `LYRAFORGE_NO_ELEVATE=1` opt-out and graceful non-elevated fallback if UAC is declined); suppressed Windows console window flashes across all isolated subprocesses (`ffmpeg`, `basic-pitch`, `dettato`, `uv`, `nvidia-smi`, PyTorch CUDA probe, and `taskkill`/`powershell` tree cleanup) via `CREATE_NO_WINDOW` and hidden `STARTUPINFO`.
- **Unified song selection & per-song multi-job transcription tracking**: added a global song switcher to the top context bar (`#topbar-song-select`) backed by an unfiltered song catalog (`allSongs`), unified song selection across Home, Library, Transcribe, Studio, and Playback so switching or uploading songs immediately updates the working song everywhere, switched transcription pipeline/progress state to track each song independently across multiple concurrent background jobs (`GET /v1/jobs`), added per-job background notifications and "other songs' transcription tasks" quick actions (`去编曲` / `切换查看` / cancel) without hijacking the current song on completion, and added direct guidance in Studio for untranscribed audio songs.
- **Transcription target no longer follows playback selection (superseded by unified selection above)**: initially decoupled transcribe target from playback selection in Round 20 before unifying per-song multi-job state and the global topbar switcher.
- **CUDA PyTorch install now actually replaces the CPU build**: PyPI's CPU wheels can be newer than the newest CUDA wheel (e.g. `2.15.0+cpu` vs `2.14.1+cu130`), so a plain `--upgrade` resolved to "no changes" and GPU install failed at verification. The installer now uses `--reinstall-package torch` against the `cu130` index (override with `LYRAFORGE_PYTORCH_CUDA_INDEX`), allowing the necessary downgrade; verified on an RTX 2070 SUPER / driver 617.42 with `torch 2.14.1+cu130`, `torch.cuda.is_available() == True`.

### Added
- **Minimalist Swiss L-Harp app icon & macOS desktop bundles**: designed a unified geometric L-Harp emblem (`packaging/icons/lyraforge.{svg,png,ico,icns}` and `docs/assets/lyraforge-icon.svg`), embedded `.ico` (16–256 px) into Windows builds/WinForms windows, `.icns` (Retina iconset) into compiled macOS `LyraForge.app` bundles and Cocoa Dock icons, updated the Web favicon and sidebar brand mark, and added CI `package-macos` + multi-platform `dev-latest` releases (`LyraForge-*-macos-arm64.zip` alongside `windows-x64`).
- **GPU acceleration managed from settings**: the settings page now detects an NVIDIA GPU and the dettato environment's PyTorch/CUDA build, lets the user pick `auto / cpu / cuda / mps` (persisted and injected as `LYRAFORGE_DETTATO_DEVICE`), and offers a one-click "install CUDA PyTorch" action that runs through the existing tool-install progress UI and verifies `torch.cuda.is_available()`.
- **Broader media format support**: `.m4s` DASH segments plus common audio (`.aac`, `.wma`, `.aiff`, `.oga`, `.opus`, `.m4b`) and video containers (`.mov`, `.avi`, `.flv`, `.wmv`, `.ts`, `.m2ts`, `.mts`, `.3gp`, `.mpg`, `.mpeg`, `.vob`, `.ogv`) are accepted by the import picker and routed through FFmpeg; decoding still depends on the installed FFmpeg build and encrypted/DRM files are rejected with a clear error.
- **dettato can use a GPU and no longer times out on long songs**: the adapter auto-detects CUDA/MPS (`LYRAFORGE_DETTATO_DEVICE=cpu|cuda|mps` overrides) and passes `--device`; transcription timeouts now scale with audio length (dettato ~10x realtime + 180 s slack, Basic Pitch ~3x + 60 s) instead of a fixed 5 minutes.
- **Playback queue as a dedicated panel**: the queue moved out of the playback page into a right-side drawer opened from the global transport bar (`队列 n`), with numbered items, current-item highlight, click-to-select, previous/next and clear actions.
- **Arrangement version management**: saved versions now show an auto-generated descriptive name (`#序号 · 风格 · 移调 · 速度`), playability ratio, note count and creation time, and can be renamed inline (`POST /v1/arrangements/{id}/label`).
- **About & license dialog**: the sidebar footer now opens an About dialog listing the version, GNU GPL-3.0 notice, source link and third-party component licenses; the "zero API key" slogan was removed.
- **Playback queue with next/previous**: queue arrangements from the studio and move with buttons or the `next`/`previous` global hotkeys; queue switching stops the current playback, re-prepares the target and reuses the focus/permission checks.
- **Configurable global hotkeys for playback (default unbound)**: `start` / `pause` / `resume` / `stop` / `next` / `previous` can be assigned user shortcuts such as `Ctrl+Alt+F9`; registration uses the Windows `RegisterHotKey` API, conflicts are reported per action, and the settings page persists them. Nothing is bound until the user sets it.
- **Configurable game process allowlist**: `windows_allowed_processes` defaults to `GenshinImpact.exe, YuanShen.exe` and can be edited in settings, alongside the existing window-title fallback.
- **Built-in one-click arrangement presets**: five validated presets per instrument (melody first, balanced, rich, slow practice, lively) exposed as buttons in the arrange studio and via `lyraforge presets list` / `GET /v1/presets`; the default workflow never calls an agent or an API.
- **Vintage Lyre (老旧的诗琴) profile**: a third 21-key instrument preset with the community-documented C Dorian / C Phrygian pitch mapping (distinct from the C major lyres), marked `unverified` until in-game calibration.
- **In-app one-click toolchain installer**: `lyraforge tools status|install` and a desktop settings card install FFmpeg, Basic Pitch and dettato on demand into `%LOCALAPPDATA%\LyraForge\tools` (or the platform equivalent). Downloads come from PyPI with SHA-256 verification; `uv` is bootstrapped from its verified wheel and manages an isolated CPython plus per-engine virtualenvs. No registry, PATH or user environment changes are made — LyraForge injects the managed paths into its child processes at startup, and explicit user environment variables still win (`src/lyraforge/toolchain/*`, `src/lyraforge/api/tool_service.py`, `apps/desktop/web/src/views/SettingsView.vue`).
- **Cross-platform music core & arranger**: Headless MIDI import/export, tempo map handling, melody prioritization, chord arpeggiation, playable-range folding/transposition, built-in 21-key presets (*Windsong Lyre* and *Floral Zither*), and separated arrangement playability vs. audio transcription fidelity scoring.
- **Audio & media transcription pipeline**: Pure-Python offline monophonic YIN transcriber (`builtin-mono`), WAV normalization, optional user-configured `ffmpeg` media extraction (`.mp3`, `.flac`, `.m4a`, `.ogg`, `.mp4`, `.mkv`, `.webm`), and isolated subprocess adapters for `basic-pitch` and `dettato`.
- **Desktop Workbench (Vue 3 + PyWebView)**: Six-view Studio Obsidian desktop workbench (Home, Library, Transcribe, Arrange Studio with interactive DAW Piano Roll, Playback console, Settings & MCP integration) with a persistent bottom transport bar for offline plucked-lyre WAV previewing.
- **SQLite Library, `.lyrapack` & Backup/Restore**: Content deduplication, exact JSON1 tag filtering, favorites/version branching, rights-confirmed `.lyrapack` sharing (audio-free and secret-free), and transactional ZIP backup/restore with rollback recovery.
- **Optional AI & MCP integration**: Built-in deterministic `RuleBasedLLMProvider`, optional private OpenAI-compatible HTTP endpoint support, and a standard `stdio` MCP server (`lyraforge mcp`, 10 typed tools) with integration templates under `integrations/` and hard confirmation gating on `play_in_game`. Not required for the default offline workflow.
- **Cross-platform CI & GitHub Releases automation**: Added Windows portable ZIP packaging, post-extraction `LyraForge.exe --self-check`, `SHA256SUMS.txt` checksum generation, rolling `dev-latest` + immutable `dev-YYYYMMDD-<sha7>` experimental pre-releases on `main`, and isolated SemVer (`vX.Y.Z`) release channels (`packaging/lyraforge.spec`, `scripts/build_windows.ps1`, `scripts/release_helper.py`, `.github/workflows/ci.yml`).

### Changed
- **Studio Obsidian UI/UX redesign (`DESIGN.md`)**: unified the six-view desktop workbench under a warm-amber-and-obsidian design system with a collapsible Studio Piano Roll inspector and 21-key dock, interactive time-ruler seek and live playhead, master-detail Library table with inline inspector, 4-step audio transcription guide, 2-column categorized Settings with 4-client MCP switcher (`Claude Code`, `Codex CLI`, `Antigravity`, `DeepSeek`), native `<dialog>` About license modal, and persistent global preview transport scrubber.
- **Developer-only wording removed from the UI**: engine cards no longer mention "ADR-0001"; they describe what each engine does and where it runs in user terms.
- **Layout and typography fixes**: advanced/optional sections are now full-width instead of leaving an empty grid cell, long paths and engine version strings wrap inside cards, and code blocks wrap instead of overflowing their container.
- **AI/Agent is now clearly optional**: the desktop navigation, home page, transcribe view and settings put the preset-driven offline workflow first; MCP / HTTP LLM integration moved into collapsed "advanced (optional)" sections, and README no longer presents AI as a prerequisite.

### Fixed
- **Windows playback started with a false `focus_lost`**: playback used to check the foreground window immediately after the in-app start click, so LyraForge's own window failed the check. Starting now enters a `waiting_focus` phase (default 10 s) and only sends keys after the game is foreground; timeouts report the actual foreground process/title without sending anything.
- **Game detection no longer depends on the window title**: the guard matches the foreground process (`GenshinImpact.exe` / `YuanShen.exe`) first, with title matching kept only as a fallback, so localized titles and fullscreen/borderless modes work.
- **UIPI permission mismatch is explained and recoverable**: when the game runs elevated and LyraForge does not, playback is blocked with an actionable message and a desktop button to relaunch LyraForge as administrator, instead of silently dropping synthetic input.
- **External transcription engines were unusable on Windows**: the Basic Pitch adapter invoked the removed `basic_pitch.inference` module (0.4.x uses `basic_pitch.predict`), child Python tools inherited the Chinese-Windows `cp936` codec and crashed on emoji progress output, and dettato was passed a file path where its CLI expects an output directory. All three are fixed and verified end-to-end with real `basic-pitch` 0.4.0 and `dettato` 2.0.0 (`src/lyraforge/transcribers/*`, `src/lyraforge/media/subprocess_utils.py`); [DEVELOPMENT.md](docs/DEVELOPMENT.md) now documents the verified isolated-environment recipe (`numpy<2`, `setuptools<81`).
- **Windows portable build could not open its desktop window**: the PyInstaller bundle omitted the dynamically imported PyWebView GUI host (pywebview, pythonnet and the WebView2 interop DLLs), so `LyraForge.exe` exited within a second without showing anything. The frozen bundle now pins `webview`/`clr`/`webview.platforms.edgechromium` and fails the build if the GUI payload is missing (`packaging/lyraforge.spec`).
- **`--self-check` never exercised the GUI host**: CI now runs `LyraForge.exe --self-check --check-gui`, and a frozen bundle always requires the GUI import, so a packaging regression fails the release gate instead of the user's desktop (`src/lyraforge/cli.py`, `.github/workflows/ci.yml`).
- **Fatal startup failures are no longer silent**: startup errors are appended with a traceback to `%LOCALAPPDATA%\LyraForge\logs\startup.log` and shown in a native error dialog on Windows/macOS (`src/lyraforge/startup_report.py`, `apps/desktop/main.py`).
- **Portable ZIP usability**: the release archive now carries `README.txt` with extraction/launch steps and the startup-log location, and packaging validation rejects archives without the WebView2/pythonnet payload (`scripts/release_helper.py`).

### Reliability & Security Highlights
- OS-native API key storage (macOS Keychain, Windows Credential Manager, or `0o600` local secret file) with plaintext SQLite migration and redaction across logs, errors, backups, and share packages.
- DNS-pinned SSRF protections for authorized direct-URL downloads and strict Creative Commons / Public Domain URL classification for open catalog queries (rejecting `NoDerivatives`).
- Hardened concurrent preview WAV rendering using isolated per-request temporary synthesis and atomic publish replacement so cancelled renders never remove another request's published preview.
- Hardened bounded subprocess execution with process-group/tree cleanup, crash-safe `.restore-txn.json` backup restore transactions, active MCP task non-eviction, cooperative cancellation, and deadlock-free log/pipe drain cleanup.

### Known Alpha Limitations
- Windows 10/11 live Genshin Impact free-play playback (`WindowsKeyboardDriver` + `ForegroundWindowGuard`) has been verified on real hardware by the maintainer, while the built-in profile JSON metadata field `calibration.status` remains `"unverified"` until a dedicated profile-metadata update.
- Complex polyphonic/vocal music transcription benefits from optional `ffmpeg` + `basic-pitch` or `dettato` (installable in-app from **Settings → Transcription Engines & GPU**, with optional NVIDIA CUDA acceleration) alongside manual Piano Roll refinement.
- No formal Stable GitHub Release or signed/notarized Windows/macOS installer has been cut yet.
